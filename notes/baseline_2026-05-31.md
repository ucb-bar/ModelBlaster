# ModelBlaster multi-network scheduler baseline — 2026-05-31

Consolidated baseline for the **GemminiAndOPUShuttleConfig** FireSim
bitstream, supersedes `notes/baseline_2026-05-28.md` and complements the
qrb head-to-head doc (`notes/qrb5165_head_to_head.md`).

## Hardware

| Tile | Hart | Backend | Notes |
|------|-----:|---------|-------|
| CPU_P#0 | 0 | gemmini + Shuttle scalar | Gemmini RoCC int8 (DIM=16), curated im2col→tiled_matmul kernel is bit-exact vs Q0.31 PyTorch golden |
| CPU_E#0 | 1 | Saturn OPU + RVV | Curated indir-gemm conv + outerprod linear/matmul exist (`kernels/rvv_opu/`) but are tagged `NUMERIC_DRIFT` — cross-backend drift constraint pins `conv2d_s8` / `linear_s8` to CPU_P |

## Solver matrix

| Solver | Where it wins | Where it fails |
|--------|--------------|---------------|
| **MOSEK MILP** | ≤ ~100 ops (no-yolo 88-op gives 25.30 ms optimal vs HEFT's 29.21 ms) | 300-op qrb_y64 doesn't converge in 1 hr (89.72 ms optimal_inaccurate, worse than HEFT) |
| **HEFT** | Fast fallback at every scale; 84.15 ms on qrb_y64 in 0.02 s | Doesn't enforce deadlines (only start bounds) |
| **PEFT** | Slightly better than HEFT on qrb_y64 (84.00 vs 84.15 ms) | Same deadline limitation |
| **CPSAT** | — | OR-Tools integer rounding collapses sub-ms ops to 1 µs (documented in scheduler_cpsat.py) |
| **Periodic-partition** (this work) | Enforces both start + end bounds via per-instance solve + ASAP-pack-on-tile merge | Slightly worse makespan than MOSEK PACKED (gives up batch-time-min for periodic correctness) |

## 2026-06-01 attempt: gemmini + rvv (plain RVV) backend pair

Tried switching to the kernel pair Dima identified as the qrb image's
(kernels/rvv + kernels/gemmini software-Q0.31). Set up:
  - `cores/chipyard_gemmini_rvv_hetero.json` registers gemmini + rvv on
    the same OPU bitstream (OPU = RVV + extensions; plain RVV runs).
  - `configs/multi_3way_qrb_y64_gemmini_rvv.yaml` drops the drift
    constraint (both backends now bit-exact-equivalent).
  - `scripts/run_gemmini_rvv_capture.sh` drives the capture with
    `BACKENDS=gemmini,rvv`.

**Picker now activates curated kernels** (kernel_picks.json shows
`conv2d_s8: curated rvv_vsmul_vnclip`, `silu_s8: curated direct`, etc.) —
the first capture where the vectorized RVV conv goes live.

**FireSim TIMED OUT at 1hr — TWICE, deterministically** (`bxi7fz29d` wall
3767s, `bhwhbyqrj` wall 3782s). Two back-to-back runs with identical
timeout behavior rules out FPGA queue contention or transient issues.
The sim ran but didn't emit `MODELBLASTER_WALL_CYCLES` markers within
the budget either time. Root cause not isolated:
  - Bitstream mismatch theory: the binary was built without OP-V custom
    extensions; plain RVV is a strict subset so it *should* run on the
    OPU unit, but a microarchitectural edge case could deadlock.
  - Runtime cost theory: the actual plain-rvv kernels are slower than
    profile_db's rvv_opu stand-in cycles predict (predicted 89.92 ms
    becomes >1hr actual would imply ~600× slowdown — implausible for
    pure compute, suggesting deadlock).

Proper fix: build a dedicated `gemmini + rvv` FireSim bitstream
(matches the qrb image's setup). That's multi-hour FPGA synthesis.

## Identified path to beat qrb 75.71 ms

1. **Conv+SiLU fusion** (kernel + graph work, scaffolded but not active)
   — eliminates the 20 ms sync wait at every conv→silu cross-tile transition
   — projected makespan ~56 ms for 1y+2d+4m (would beat qrb by 26%)
   — `pipeline/reference_kernels.py:CONV2D_SILU_S8` registered, detector
     fires on Conv→SiLU pairs; **doesn't fire on yolov8** because its IR
     has Conv→BN→SiLU. Needs Conv+BN+SiLU 3-fold OR BN-into-Conv pre-pass.

2. **Activate the curated rvv_opu kernels** (currently silently inactive)
   — `kernels/rvv_opu/{silu,conv2d_s8,linear_s8,cat2/3/4}.c` all exist
   — picker invokes verify subprocess which loses `west` from PATH and
     falls back to scalar reference for EVERY curated rvv_opu kernel
   — `MODELBLASTER_CURATED_VERIFY=0` was tried — silently breaks the
     Zephyr build at 10s with no diagnostic (separate bug)
   — Fix path: either inherit shell PATH into the verify subprocess
     or bypass picker by writing kernels directly into
     `examples/<model>/<quant>/generated/<target>/kernels.c`

3. **Compile yolov8 via Merlin/IREE** (architectural change)
   — qrb image was generated this way (`samples/merlin_hetero_runner/`
     in zephyr-chipyard-sw dev branch). IREE auto-fuses Conv+BN+SiLU
     during codegen. Out of scope for ModelBlaster baseline.

## What's NOT in scope (and why)

- **Power / cache / branch metrics**: bitstream lacks Autocounter probes; needs rebuild.
- **Other yolov8 input sizes** (32, 96, 128): only @160 (too big) and @64 covered.
- **Other quant modes** (gemmini_q31, fp16): hetero scheduling work is locked to int8 + gemmini/rvv_opu pair.
- **Energy / power**: no on-chip telemetry on this bitstream.
