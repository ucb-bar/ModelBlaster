# Methodology: baseline-dronet-arm-a-matrix-2026-05-26

Arm A (curated, no LLM) baseline across the dronet matrix on spike,
3 replicates per cell. Pairs with `baseline-dronet-arm-a-2026-05-26`
(the original scalar-only baseline) — the full A matrix is the union.

## Approach
Arm A driver, BACKEND=reference, OPTIMIZE=0, RUNNER=spike (forced via
`--runner-override spike` for cells whose workload row defaults to
firesim). 3 replicates per cell, captured under session
`baseline-dronet-arm-a-matrix-2026-05-26` for attribution.

## Cells captured

| Cell | Curated kernel coverage | Notes |
|---|---|---|
| `dronet_scalar_smoke` | none — all generated reference | (already in baseline-dronet-arm-a-2026-05-26) |
| `dronet_rvv_smoke` | RVV ihwoc conv2d + linear + others | |
| `dronet_rvv_opu_int8` | OPU indir-gemm conv2d + linear | functional-only on spike (per gotcha #6) |
| `dronet_gemmini_int8` | gemmini tiled_conv + im2col | |
| `dronet_gemmini_q31_int8` | gemmini_q31 conv2d + add + relu + linear | **accuracy fail** — see below |

## Results

| Cell | Wall cycles | Speedup vs scalar | bit_exact | linf |
|---|---|---|---|---|
| `dronet_scalar_smoke` | 4,546,550 | 1.00× (baseline) | ✓ | 0.0 |
| `dronet_rvv_smoke` | 4,612,350 | 0.99× | ✓ | 0.0 |
| `dronet_rvv_opu_int8` | 4,546,550 | 1.00× | ✓ | 0.0 |
| `dronet_gemmini_int8` | 188,150 | **24.2×** | ✓ | 0.0 |
| `dronet_gemmini_q31_int8` | 69,050 | **65.8×** | **✗** | 72.0 |

All wall cycles deterministic across the 3 replicates per cell (stddev
= 0 — spike is fully deterministic).

## Observations

- **RVV on spike isn't faster than scalar.** The smoke workload is too
  small for vectorization to amortize setup; expect different numbers
  on full dronet (not the smoke slice).
- **RVV-OPU on spike == scalar cycles.** Spike doesn't actually execute
  OPU instructions usefully (per gotcha #6, spike treats accelerator
  ops as atomic). Cycle count is functional-only; the real comparison
  needs FireSim.
- **Gemmini wins on cycles.** 24× speedup over scalar, bit-exact —
  this is the strongest spike-side result.
- **gemmini_q31 fails verify with linf=72.0.** The Q31 path expects a
  per-bitstream `gemmini_params.h` (per the comment block in
  `pipeline/backends.py:266-280`); we vendored chipyard's generic
  DIM=16 params, which mismatches the Q0.31 acc-scale path. The 69k
  cycle count is real (the kernel runs) but the numerics drift. To
  unblock Q31 verify: drop a Q31-specific params header at
  `cores/gemmini/include/gemmini_params.h` (generated by
  `Q31GemminiRocketConfig` chipyard bitstream gen).

## Known gaps in this baseline

- **No `dronet_hetero_int8`.** Spike-hetero rejects the schedule
  fixture (`schedule_fixtures/dronet_hetero_gemmini_opu.json`) because
  it specifies `CPU_P` of kind `rvv` but the registry
  `cores/chipyard_gemmini_opu_hetero.json` only has gemmini + rvv_opu
  cores. The fixture was generated against a different mapping;
  regenerate with `scripts/gen_hetero_schedule.py` against the
  current registry, or pass `--cpu-p-kind rvv_opu --cpu-e-kind
  gemmini` to remap. Deferred since the cell is documented as
  "use firesim for the baseline capture" per the harness NOTE.

## Reproducing this report

```bash
git checkout 923d802
source scripts/setup_benchmark_env.sh
uv run mb-cost session start baseline-dronet-arm-a-matrix-2026-05-26 \
    --label "Arm A matrix baseline"
for wl in dronet_rvv_smoke dronet_rvv_opu_int8 dronet_gemmini_int8 dronet_gemmini_q31_int8; do
    for rep in 1 2 3; do
        OVR=""
        case $wl in
            dronet_rvv_smoke) ;;
            *) OVR="--runner-override spike" ;;
        esac
        uv run python -m modelblaster.benchmarks.arms.arm_a_curated \
            --workload $wl $OVR
    done
done
uv run mb-cost session end
uv run mb-cost export --full baseline-dronet-arm-a-matrix-2026-05-26 \
    --session baseline-dronet-arm-a-matrix-2026-05-26
```
